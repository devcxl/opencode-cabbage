# v2.1.0 发布说明

- **版本**：2.1.0（minor）
- **范围**：`v2.0.0..d2a031d`（14 commits）
- **包名**：`@devcxl/opencode-cabbage`
- **发布日期**：2026-11-10
- **升级**：`opencode plugin add @devcxl/opencode-cabbage@2.1.0`

## 概览

本版本完成 v2.0.0 之后的简化与安全收敛：Agent 权限声明迁移为 V2 原生规则并收紧测试命令白名单，发布产物去掉开发期文件，Stage 契约折叠进编排器提示词，session-index 收敛为最小绑定，Codex 兼容层对齐并加上防漂移守卫。

- 运行环境不变：Node ≥ 24，OpenCode v2（`@opencode/plugin` 2.x，已在 v2.0.28 实测）。
- 仅含一处打包层破坏性变更（移除未文档化的 `./server` 子路径导出），详见下文。
- v2.0.0 的全部能力保持可用：7 个 slash command、12 个 flow skill、6 个 agent、`goal` 与 `cabbage` 两个工具。

## 亮点

1. **Agent 权限 V2 原生化 + 测试命令白名单收敛**（`0740907`，PR #162/#164）
   - agent frontmatter 从 V1 的 `permission:` 映射 + `tools:` 布尔开关，改为 V2 原生 `permissions: PermissionRule[]` 数组（顺序即优先级）。
   - `<profile-test-command>` 占位符渲染从"取命令首 token"改为"取 `{testPaths}` 前的安全前缀"：`npm test -- {testPaths}` 渲染为 `npm test -- *`，不再退化成 `npm*` 式权限放大。
   - 命令无法提取前缀（命令为空、或 `{testPaths}` 前无固定前缀）时**丢弃该 allow 规则**，由兜底 `deny` 接管，而非放宽为 `*`。
   - prompt-lint 新增权限声明守卫；`test/adversarial/06-permission-bypass` 同步覆盖新匹配语义。

2. **发布产物收敛**（`75d623a`，PR #149/#156）
   - 构建改用 `tsconfig.build.json`，开发期 `prompt-lint` 不再打进 tarball。
   - `test:pack` 增加三道守卫：`exports` 必须仅含 `.` 与 `./package.json`、禁止 `dist/flowrun/` 残留、禁止 `dist/plugin/prompt-lint` 残留。
   - tarball 实测：151 文件 / 193.9 kB，含 `dist/kernel/`、内置 cabbage 引擎（`vendor/cabbage`）、Codex 插件文件（`.codex-plugin`、`codex-skills`、`hooks`）。

3. **Stage 契约单一来源折叠**（`ecbf22e`，PR #150/#158）
   - 删除独立 `assets/prompts/stage-contract.md`（不可达的"单一来源"）与加载期 `_prompts` 拷贝死机制；阶段顺序/完成权威/门禁规则内嵌到 `assets/agents/dev-lifecycle.md`《阶段契约》章节。
   - 7 条命令模板与 `bootstrap.md` 的悬挂引用同步清理，`docs/guides/{architecture,configuration}.md` 对齐。

4. **状态权威收敛**（`ea9305b`、`1bdd012`、`4aec6dc`，PR #151/#157、#161/#163、#145/#154）
   - session-index 折叠为最小绑定，goal 成为唯一状态权威；删除内核移除后的孤儿导出与写-only 字段。

5. **Codex 兼容层一致性修复**（`e5dab18`，PR #159）
   - hook 清单与缺失引用对齐，`codex-skills/agent-dev-lifecycle` 阶段契约补齐；`session-start` 提示词新增 `@flow-change` / `@flow-incident` / `@flow-docs`。
   - 新增防漂移守卫测试（`test/plugin/codex-compat.test.ts`）：skill 清单、agent 引用归一、`plugin.json` 版本与 `package.json` 同步。
   - Codex 清单描述修正：9 → 12 个 flow skills（实际目录已是 12 个）。

6. **文档与治理**（`d2a031d`、`67fef2e`、`bb53f57`、`206d9bd`、`326ef67`）
   - `AGENTS.md` 新增 Agent skills 工作流章节（issue tracker / triage 标签 / domain docs），Project Profile 明确测试命令权限边界。
   - Jekyll 时代文档退役、ADR 0007 退役与编号/引用修复、7 项简化候选提案归档。

## 破坏性变更与升级注意

1. **`@devcxl/opencode-cabbage/server` 子路径导出移除**（`1bdd012`）
   - 该别名自首个提交起存在、2.0.0 仍发布，指向与包根相同的 `dist/index.js`。移除后 `import ... from "@devcxl/opencode-cabbage/server"` 会解析失败。
   - 迁移：改为从包根导入（导出对象相同）。仓库文档从未记录该子路径，未发现外部使用证据。

2. **Agent 资产 frontmatter 格式变更**
   - `permission:`（map）+ `tools:`（boolean）不再解析，取而代之的是 `permissions:`（`{action, resource, effect}` 数组）。
   - 影响面：仅自建/覆盖同名 agent 的用户。插件内置 6 个 agent 资产已全部迁移；用户自定义同名 agent 仍按 skip-if-exists 保留，不会被覆盖。

3. **测试命令权限收紧（行为变更）**
   - 旧：按 Profile 测试命令首 token 放行（`npm test -- {testPaths}` → `npm*`）。
   - 新：按固定前缀放行（→ `npm test -- *`）。若某项目的测试命令形式特殊（例如 `{testPaths}` 位于命令开头，或前缀为空），该 allow 规则会被丢弃，测试命令回落为 `ask`（auto 模式下等效拒绝）。
   - 升级前建议确认根 `AGENTS.md` 的 `test command` 是"固定前缀 + `{testPaths}`"形式。

4. **V1 模型字段兼容分支移除**
   - goal 会话快照的 `profile.model` 不再接受 1.x 形状 `{providerID, modelID}`；形状不完整时**不报错**，仅跳过 `switchModel`（沿用当前模型）。仅影响从 1.x 升级且仍有 active goal 的极端场景。

5. **命令 frontmatter `model` / `subtask` 静默忽略**
   - 原先会打印"V2 不支持，已忽略"的告警，现直接忽略（2.0.0 起本就不支持）。

6. **内部契约文件删除**
   - `assets/prompts/stage-contract.md` 与 `<skillsDir>/_prompts/` 拷贝机制移除。技能安装目录按插件版本隔离（`skills@<version>/`），升级即重新落盘，无需手工清理。

## 已知限制

1. **测试命令前缀提取是启发式**：非"固定前缀 + `{testPaths}`"形式的 Profile 会失去测试命令白名单（回落 `ask`）。
2. **已有同名 agent 不被覆盖**：用户在自身配置里定义的同名 agent 会保留其权限声明，插件的新白名单对其不生效（设计如此，skip-if-exists）。
3. **`release-draft.yml` 门禁弱于 CI**：只跑 prompt-lint / build / test，不含 typecheck 与 test:pack。
4. **发布顺序不可逆**：GitHub Release 一旦发布，npm 工作流失败会留下"有 Release、无 npm 版本"的错位；tag 不可覆盖，只能修因后发新 patch 版本。
